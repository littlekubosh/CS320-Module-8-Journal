## How can I ensure that my code, program, or software is functional and secure?

I believe the best way to ensure that software is functional and secure is to establish clear requirements and develop tests that verify those requirements are being met. Throughout this course, I used JUnit to test the functionality of my Contact, Task, and Appointment services. My tests included valid inputs, invalid inputs, boundary values, and attempts to perform operations that should not be permitted. By the end of the project, I had developed 73 JUnit tests that all passed, with 93% instruction coverage. However, I also learned that passing tests do not necessarily mean that software is free of defects. For example, my original Appointment class allowed its Date object to be modified externally without passing through the validation methods. Correcting this issue taught me the importance of reviewing code for unexpected interactions and considering potential vulnerabilities that may not be addressed by the original test cases.

## How do I interpret user needs and incorporate them into a program?

I approach user needs by first identifying what the user expects the software to accomplish and translating those expectations into specific, testable requirements. I think it is particularly important to clarify any requirements that are vague or could be interpreted in multiple ways before development begins. In my professional experience with electrical commissioning, unclear requirements can lead to misunderstandings about how a system is supposed to function, and I believe the same principle applies to software development. During this course, I used the provided requirements to determine how each service should behave, including restrictions on character lengths, required fields, and permitted operations. I then developed tests based on those requirements to verify that the completed software behaved as intended.

## How do I approach designing software?

When designing software, I prefer to begin by understanding the requirements and determining how the program should be organized before writing the code. I try to separate responsibilities between classes and keep individual methods focused on specific tasks. For example, in my projects, the Contact, Task, and Appointment classes were responsible for storing and validating their respective information, while the service classes handled operations such as adding, updating, and deleting records. This separation made the code easier to understand, test, and maintain. I also believe testing should be considered throughout development rather than waiting until the program is complete. Developing automated tests alongside the code allows me to identify problems earlier and verify that future changes do not introduce new defects. Moving forward, I plan to continue improving my designs through testing, code reviews, and feedback from other developers.
